# CLM-0013

## claim

Month-one UI should expose only broad, confidence-gated pulse-trend states, not PRV/HRV-derived states.

## status

PROVISIONAL

## supporting_papers

- `knowledge/papers/PAPER-2013-SUN-NONCONTACT-PRV-FRAMERATE.md`: PRV work used 200 fps iPPG and calls for stronger validation.
- `knowledge/papers/PAPER-2015-MORENO-FACIAL-VIDEO-HRV.md`: HRV/PRV agreement was posture-dependent and better supine than sitting.
- `knowledge/papers/PAPER-2023-VAN-ES-CONTACTLESS-CARDIOVASCULAR-ASSESSMENT.md`: average pulse rate is easier than many PRV features.
- `knowledge/papers/PAPER-2015-KIEHL-MULTI-IMAGER-PRV-MOTION.md`: PRV is sensitive to motion/source configuration.
- `knowledge/papers/PAPER-2018-FALLET-SIGNAL-PROCESSING-CARDIOVASCULAR.md`: realistic iPPG needs SQI and rejection before advanced features.

## contradicting_papers

- none in repository

## applicability_conditions

- Month-one desktop beta UI.

## confidence_rationale

The source base contains PRV feasibility evidence, but not enough for uncontrolled chat UI.

## product_implication

Use only broad pulse-trend/reaction states from validated HR windows; keep PRV/HRV as research-only.
